# 公司釣魚郵件演練執行手冊

## 1. 演練目標與範圍

觀察同仁是否會辨識未預期的文件分享通知、透過獨立管道查證、主動通報。第一輪可從 RECT（洗片／造粒）與 REYT（SRF）各挑一小組公司信箱試跑，再依驗收結果決定擴大範圍。

| 角色 | 工作 |
|---|---|
| 部門主管 | 核定受測範圍、時間與結果存取人員，決定開始、暫停與結案。 |
| 資訊系統工程師 | 部署網站、檢查測試信與通報流程、安排核准平台的演練批次、彙整成效。 |
| 資訊服務窗口 | 登錄來信、辨識演練與真實通報、依公司程序處置真實事件。 |
| 廠區窗口 | 協調班別與收信時段，避免影響換班與關鍵作業。 |

名單限於核准的公司信箱。供應商、客戶、個人信箱及產線控制電腦排除在首輪。受測同仁若需在廠外參與，先確認其一般工作網路能開啟內部演練頁。

## 2. 內網部署

1. 解壓縮，直接用瀏覽器開啟 index.html，預覽資料外洩情境。網址末尾加上 #malware 可查看中毒情境。
2. 將 **index.html** 放上公司核准的 HTTPS 內網靜態站，設在獨立目錄，例如 /security-training/index.html。手冊保留給執行人員。
3. 預設情境用正式頁面網址。中毒情境在同一網址末尾加上 #malware。若郵件平台會改寫網址，請用測試信驗證改寫後仍會開啟正確情境。
4. 網頁本身無登入、表單、附件、外部連線或追蹤程式。若公司已核准郵件演練平台，由平台提供個別點擊事件與彙總報表。本頁無法產生個別點擊率。內網站台若有存取紀錄，依公司規範限制存取及保留。
5. 結案時可將入口替換成「演練已結束」頁，或依內部作業下架。

## 3. 寄送及驗收

| 時點 | 工作與通過條件 |
|---|---|
| 寄送前 3–5 個工作天 | 核定名單、通報窗口、演練時段與保留期限。確認外部地址排除、內網網址有效。 |
| 寄送前 1 個工作天 | 用資訊部測試信箱試寄，從桌機、手機及預定網路點開。確認正確情境、首屏揭示演練、郵件通報能抵達窗口。 |
| 正式演練日 | 由核准的公司信箱或演練平台寄送到核准名單。建議先小組試辦、觀察 1–2 個工作天。 |
| 演練期間 | 收到通報時核對原始郵件與核准批次。陌生連結、仿冒信或疑似真實事件依公司事件流程處理。若連結錯誤、名單外流或影響正常營運，停止後續批次並通知主管。 |
| 截止後 1–3 個工作天 | 關閉演練、發回饋信、彙整成效，並按核准期限處理測試名單與明細。 |

試寄也應確認公司郵件防護維持正常。如平台可辨識安全掃描等自動事件，統計時排除。若無法區分，結果標示為未排除自動事件，或將點擊率列為無資料。

## 5. 演練成效與改善

| 指標 | 統計口徑 |
|---|---|
| 送達人數 | 實際成功送達的不同收件者。排除退信。 |
| 點擊率 | 有可信點擊事件的不同收件者 ÷ 送達人數。每位收件者只計一次。缺可靠事件來源時填「無資料」。 |
| 通報率 | 有效通報該演練信的不同收件者 ÷ 送達人數。重複通報只計一次。 |
| 首次通報時間 | 同批首次有效通報時間減去該批成功送達的起始時間。無通報則填「未通報」。 |

各批次分開計算。向主管呈報彙總成效與改善事項，小樣本視情況併入大組。首次建立基線，下一輪比對通報率、首次通報時間與點擊率。若通報偏少，優先確認同仁找不找得到通報入口，再安排一次短宣導。
